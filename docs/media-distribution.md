# Media implementation and distribution

The media decoder uses FFmpeg 4.4.6, LGPL-2.1-or-later, from the pinned `third_party/ffmpeg` submodule. GPL, nonfree, encoders, network, filters and unrelated codecs are disabled in `scripts/build-ffmpeg.sh`. FFmpeg avutil, avcodec and avformat remain separate shared libraries. The application explicitly loads them in dependency order for pre-4.3 Android loaders. No FFmpeg code is statically merged into the application JNI library.

For every published APK, distribute the matching `:app:correspondingSource` ZIP alongside it. It contains the exact FFmpeg sources, the build scripts, the JNI adapter sources, project build files, dependency source and notices. Preserve submodule commit identities in `third_party/README.md`. Do not substitute an upstream download link for the matching source archive. The app's notice page includes the LGPL text and this notice.

To build the decoder libraries: initialize the pinned submodules; install NDK r10e at `.tools/android-ndk-r10e`, Git Bash and the Android SDK; run `bash scripts/build-ffmpeg.sh`. The fixed configuration is recorded in each `app/build/ffmpeg/<abi>/ffbuild/config.mak`. GCC 4.9 targets API 8 ARMv7/VFPv3-D16 and API 9 x86. Assembly is disabled, including NEON, for the fixed software workload. This does not establish device-level loading compatibility; verify with `scripts/check-legacy-native.ps1` and real devices.

Replacement/relinking: rebuild API-compatible avutil/avcodec/avformat with the same public ABI and SONAMEs (`libavutil.so`, `libavcodec.so`, `libavformat.so`). Replace those files under `lib/<abi>/` in an unpacked APK, reassemble with ordinary Android packaging tools, sign with your own v1-compatible key and install it. An existing installation signed with a different key must be removed first or the application ID changed. The application does not enforce integrity checks on those libraries and does not forbid replacement or reverse engineering for debugging modifications to the LGPL libraries. Test corpus hashes check input files only. Native decoder modifications form a separate performance comparison group and must be identified when results are shared.

Mbed TLS 2.28.10 supplies AES/GCM/SHA-256 with a minimal benchmark-only configuration, no TLS/networking. libjpeg-turbo 2.1.5.1 (scalar accurate DCT) and libpng 1.6.43 supply software image decoding. They are not device security services and only process bundled fixed test assets.

Video source: Sintel trailer, Blender Foundation, CC BY 3.0, https://durian.blender.org/sharing/ . Clips are resized, re-encoded, stripped of audio and shortened; they are not original trailer files. JPEG photos derive from the same source. PNG transparency test patterns are generated by FFmpeg testsrc2. Exact encoding parameters, source and output SHA-256 hashes are in `app/src/main/assets/media/manifest.json`; `scripts/generate-media.ps1` is the generation recipe. Keep the frozen assets under version control; regeneration changes the corpus and requires a new protocol identity.

Current validation limits: API 8/9 device loading, vendor hardware decoding, real frame presentation, eight-core scheduling, peak memory and temperature behavior require physical-device runs. Capability declarations and successful builds alone do not prove those properties.
